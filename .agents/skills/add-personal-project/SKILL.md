# Add Personal Project

Resolve paths against the portfolio root. Read [AGENTS.md](../../../AGENTS.md)
and the [personal-project workflow](../../../docs/projects/README.md), the source
of truth for intake, content, media and verification. Inspect `content/projects/`,
the shared Projects renderer and any existing source notes before asking questions.

## Establish the evidence

Reuse information already supplied, including informal notes in either language.
When a repository is supplied, inspect its README, manifest and lockfile,
specifications or architecture, relevant implementation, tests and latest
validation records. Record the inspected revision. Distinguish a test's presence
from evidence of its execution, and local, CI and public checks from one another.
Repository instructions do not authorize deployment or unrelated side effects.

Maintain `docs/projects/<id>.md` in English with repository-verified facts and
paths/revision, owner statements, editorial proposals and unresolved questions.
Do not infer motivation, personal ownership, production maturity or the proportion
of AI-generated code from dependency lists or commit history. Distinguish delivered
behavior, observed results and intended benefits; never invent metrics or dates.

Ask only about gaps that affect truthful publication or presentation. Missing
optional dates, video or metrics do not require a questionnaire. Establish the
motivation, problem or hypothesis, meaningful capabilities, engineering decisions
and tradeoffs, personal participation, AI assistance when applicable, validation
and lessons. Connect skills to concrete behavior rather than ratings or generic
claims. Explain experiments as experiments, without turning personal lessons into
universal comparisons of development methods.

## Prepare and integrate

Prepare natural English and Spanish copy and identify real visual resources.
Inspect images before selecting them. Prefer actual interface captures and use
a static cover without enlargement; reserve the shared accessible image modal
for additional gallery images. Keep capture
activity within authorized, isolated demo data. Do not synthesize screenshots,
invent video locations or generate a video. Propose supplied video placement only
after inspecting the file and its accessibility needs.

Present the organized narrative, important uncertainties and presentation for
approval before integrating a new project. Honor proposal-only stages. Existing
approval for the concrete proposal persists; do not request it again simply
because the skill is being used. After approval, update shared identifiers/order,
resources, both localized records and source notes using the existing renderer.
Use the brief portfolio entry and shared localized case route; a normal addition
updates data/assets, without a custom route file, component or section redesign.
Group the narrative for reading instead of exposing every data field. Omit video
duration/file badges, internal task IDs and incidental execution bookkeeping from
public copy. Place supplied video near the start and final documentation links in
a vertical list preserving their primary-text underline style. Keep optional material absent instead of publishing empty placeholders.

## Verify

Follow the workflow's checks for the authorized scope. Check bilingual parity,
capability coverage, evidence attribution, media and resource links, localized routes/metadata, topic and legacy
fragments, language switching, return navigation, keyboard/focus,
no-JavaScript reading, reduced motion, both appearances and responsive layouts.
Verify image modal Escape, backdrop, close control and focus restoration.

Report changes, executed checks and remaining factual gaps. Preserve the session's
branch, commit, push and deployment constraints. Refine the maintained workflow
only when owner feedback or actual usage reveals a reusable improvement.
